# v1.0.0-preview.7: no Logos access for any receiver, and a Python receiver

This source preview needs **no Logos access for any receiver**: Logos's contract 0.25.0 is now public, so the Go, Rust, C/C++ and Python receivers build from public sources, and the npm package installs from npmjs.org without credentials. Only the `/client` entry, and building the npm package from source, still need the private `@bitspark/logos-kernel`. It adds a **Python receiver**, and CI now requires **every receiver to decide alike**. It is for consumers such as bitmachine (#39, #42).

| Language | Where | How to depend on it |
|---|---|---|
| TypeScript | the npm package `@bitspark/thesmos` | the archive attached to this release |
| Go | `core/go` | `github.com/Bitspark/thesmos/core/go@v1.0.0-preview.7` (tag `core/go/v1.0.0-preview.7`) |
| Rust | `core/rs`, crate `bitspark-thesmos` | git dependency at tag `v1.0.0-preview.7` |
| C and C++ | `core/cpp` | CMake `add_subdirectory` or FetchContent with `SOURCE_SUBDIR core/cpp` at tag `v1.0.0-preview.7` |
| Python | `core/py`, module `thesmos`, the Rust receiver behind PyO3 (#50) | `pip install "git+https://github.com/Bitspark/thesmos@v1.0.0-preview.7#subdirectory=core/py"` with Rust 1.96; its PEP 440 version reads `1.0.0rc7` |

**Changes since preview.6**
- **Public dependencies** (#57): Logos's contract moves from 0.24.0 in the private Bitspark/logos repository to the public 0.25.0, from npmjs.org, crates.io and the Go module `github.com/Bitspark/logos-contract/contract/go` (Bitspark/logos#3882). 0.25.0 only adds the contract's new `typed` module; the checker thesmos uses is unchanged. The optional `/client` peer `@bitspark/logos-kernel` moves to 0.25.0 and is still a private GitHub package. CI needs no Logos source token.
- **Python receiver** (#50): `core/rs` behind PyO3 as the module `thesmos`, with type stubs.
- **C ABI** (#48): the authentication callback now returns `int32_t` (`THESMOS_AUTHENTICATED`, `THESMOS_NOT_AUTHENTICATED`, `THESMOS_ADAPTER_FAILED`). An adapter that fails therefore denies as `invalid-proof`, as in every receiver. C callers return the constants; C++ callers only recompile.
- **Differential test** (#51, #52): CI generates seeded inputs, including pairs at and just past every limit, and requires TypeScript, Go, Rust, Python and C++ to reach the same decision, result code and step count, with no receiver panic.
- **Consumer builds** (#52): CI builds each receiver the way a consumer gets it.
- **Release workflow** (#54): this release is the first made by `release.yml`.
- **Language overview** (#55): `docs/languages.md` shows what each language offers, linked to the code that implements it.

**If you use Logos types directly.** thesmos's API carries Logos's clause type (`SpaceFacts.Clauses` in Go, `SpaceFacts::clauses` in Rust). A Go consumer that imports the contract itself switches to `github.com/Bitspark/logos-contract/contract/go` v0.25.0. A Rust consumer depends on `logos-contract` 0.25.0 from crates.io, because a git dependency on Bitspark/logos is a different crate and its `Clause` will not match. TypeScript carries it too (`SpaceFacts.clauses`) and keeps the package name `@bitspark/logos-contract`: a direct dependency on it moves to 0.25.0 as well, or npm installs a second copy whose `Clause` and `Term` classes are not the ones thesmos uses.

The frozen revision-3 law, all eight frozen artifacts, the native proof format and remote contract v1 are unchanged.

**Qualification**
- **Receivers:** every receiver job ran every step in [run 42449415742, attempt 1](https://github.com/Bitspark/thesmos/actions/runs/42449415742) on the version commit `b82f387`, with no Logos token.
  - TypeScript: 119 tests.
  - Go: both packages ok, with all modules verified.
  - Rust: 7 + 1 tests on Windows, Linux and macOS.
  - C/C++: ctest 2 of 2 on Linux and macOS.
  - Python: 21 tests on Windows, Linux and macOS, each with CPython 3.10 and 3.13.
  - Differential: 1,620 cases for each of two seeds, with TypeScript, Go, Rust, Python and C++ deciding every one alike.
  - Consumer builds: Go, Rust, Python and C++ each accepted the Archon proof after 28 checked steps and denied it with one changed byte.

  The release commit adds only these notes to that commit, so its `core/` tree is identical.
- **npm package:** the archive is the `thesmos-package` artifact that check.yml built and tested from the release commit; `release-manifest.json` names that run, the qualifying run and the archive's SHA-256, and `SHA256SUMS` covers both files.
- **Anonymous install:** the qualifying run's archive, installed with `@bitspark/archon` 0.16.0, npmjs.org as the only registry and no credentials, verified the TypeScript-signed Archon proof and denied it with one changed byte.
- **Release:** made by the `release` workflow, which checked the qualification above through the API and ends by verifying that both tags resolve to the release commit, including through proxy.golang.org.
